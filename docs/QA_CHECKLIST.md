# 実機確認の手順書

**目的:** 自動テストで押さえられない挙動を、実際の環境で1つずつ確かめる。
自動で確認できる範囲（ユニット・E2E・RLS・ビルド）は
[docs/ACCEPTANCE_CHECKLIST.md](./ACCEPTANCE_CHECKLIST.md) にまとめてある。
**ここに書くのは、動かさないと分からないものだけ。**

**所要:** 通しで40〜60分（AIの読み取り待ちを含む）。
**ただし、下の表の大半は `pnpm qa:live` で自動で流せる**（0.4）。

---

## 0. 準備

### 0.1 環境

公開手順は [docs/DEPLOY.md](./DEPLOY.md)。確認は**本番と同じ構成**に対して行う
（ローカルの `pnpm dev` では、Realtimeと保管期間の挙動が本番と揃わない）。

### 0.2 確認用の鍵

保管期間の確認で、取り込み日時をさかのぼらせる必要がある（30日待てないため）。

```bash
export SUPABASE_URL=https://xxxx.supabase.co
export SUPABASE_SERVICE_ROLE_KEY=...   # Supabase の Settings → API
```

> **サービスロールキーはRLSを迂回する。** 確認用の案件にだけ使い、終わったら
> シェルの履歴から消すこと。

### 0.3 利用者を2人用意する

同時編集の確認に、別々のブラウザ（またはシークレットウィンドウ）で
ログインした利用者が2人要る。管理者1人＋作業者1人が望ましい。

- **Aさん**（管理者）… 通常のウィンドウ
- **Bさん**（作業者）… シークレットウィンドウ。案件の担当者に割り当てておく

## 0.4 自動で流す（`pnpm qa:live`）

**この手順書の大半は、実際のブラウザ2つを動かして自動で確認できる。**
人がやると30分かかるうえ、`4-9`（別々の箇所を同時に直す）のように
「ほぼ同時」を人の手で再現しにくい項目がある。

```bash
LIVE_BASE_URL=https://<本番URL> \
LIVE_ADMIN_EMAIL=... LIVE_ADMIN_PASSWORD=... \
LIVE_WORKER_EMAIL=... LIVE_WORKER_PASSWORD=... \
SUPABASE_URL=https://xxxx.supabase.co SUPABASE_SERVICE_ROLE_KEY=... \
LIVE_KOSEKI_DIR=/path/to/確認用の戸籍 \
pnpm qa:live
```

渡す環境変数と、それで流せるようになる範囲:

| 環境変数 | 流せるようになる項目 |
|---|---|
| `LIVE_BASE_URL` | 1-1〜1-3・1-5、未ログイン時のアクセス制御 |
| `LIVE_ADMIN_*` | 2（取り込み）、6（出力） |
| `LIVE_WORKER_*` | 4（同時編集）、5（オフライン）、7-2 |
| `SUPABASE_URL` ＋ `SUPABASE_SERVICE_ROLE_KEY` | 1-4、3（保管期間・削除で実体が消えるか） |
| `LIVE_KOSEKI_DIR` | 2-2〜2-8（確認用の戸籍を置いたディレクトリ） |
| `LIVE_VIEWER_*` ＋ `LIVE_PROJECT_ID` | 7-3（閲覧のみ） |

**足りないものは失敗ではなく skip になる**（何が足りないか理由が出る）。
手元にある分から流して、あとから足していける。

案件は既定で**その場で作る**（`実機確認 …` という名前）。実際の顧客の案件を
確認に使わせないため。特定の案件で確認したいときだけ `LIVE_PROJECT_ID` を渡す。

> `SUPABASE_SERVICE_ROLE_KEY` はRLSを迂回する。確認用の環境にだけ渡し、
> 終わったらシェルの履歴から消すこと。

**手でしか確認できないもの**（自動では流せない）:

| # | 内容 | 理由 |
|---|---|---|
| 2-1 | PDFのドラッグ＆ドロップ | OSのドラッグ操作は再現できない |
| 2-6 | クリップボードからの貼り付け | OSのクリップボードが要る |
| 2-7 | 横倒しの写真の向きが直るか | 読み取り結果を人が見て判断する |
| 2-9/2-10 | 赤字が消える・残る | 原本を見ながら値を入れる必要がある |
| 3-3 | Storageの画面で実体を見る | 自動側はAPIで確認済み（3-2/3-3） |
| 4-7 | ドラッグで動かした位置が相手に出る | 人の目で「ぬるぬる動くか」を見る |
| 6-1〜6-3 | 書き出したPDF・Excelの中身 | ファイルが落ちる所までは自動、中身は人が見る |
| 7-1 | 担当から外す操作 | 管理者の画面操作を伴う |

## 1. 設定の確認（3分）

| # | 手順 | 期待する結果 |
|---|---|---|
| 1-1 | `https://<本番URL>/api/health` を開く | `supabaseConfigured: true` |
| 1-2 | 同上 | `noTrainingConfirmed: true`（falseなら読み取りが動かない） |
| 1-3 | 同上 | **`realtimeEnabled: true`** |
| 1-4 | `pnpm qa:fixtures status` | 「Realtimeの配信（tree_revisions）: 有効」 |
| 1-5 | `/api/health` | **`region: "hnd1"`**（サーバー処理が東京。DBと同じ場所） |

> `realtimeEnabled` が false なら、Supabase の Database → Replication で
> `tree_revisions` を有効にする。**無効でも保存は動く**ため、
> 「他の人の変更が入ってこない」という形でしか現れず、
> しかもそれは「誰も編集していない」と見分けがつかない。
