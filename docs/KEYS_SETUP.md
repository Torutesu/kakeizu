# APIキーとトークンの取得手順

本番デプロイに必要な4つの値を用意する手順。**所要15分程度**。

デプロイ全体の流れは [DEPLOY.md](./DEPLOY.md)、データ利用の要件は
[AI_DATA_POLICY.md](./AI_DATA_POLICY.md) を参照。

---

## 用意するもの

| 値 | 用途 | 使うタイミング |
|---|---|---|
| `SUPABASE_ACCESS_TOKEN` | Supabaseプロジェクトの作成・スキーマ適用 | **構築時のみ** |
| `VERCEL_TOKEN` | Vercelへのデプロイと環境変数の設定 | **構築時のみ** |
| `GEMINI_API_KEY` | 戸籍の解析 | 常時 |
| `ANTHROPIC_API_KEY` | 2モデル照合（推奨） | 常時 |

**上2つは構築が終わったら失効させます。** アプリの実行には使いません。
下2つはVercelの環境変数として残り続けます。

---

## 1. Supabase アクセストークン

1. https://supabase.com/dashboard/account/tokens を開く
2. 新しいトークンを生成する（名前は `kakeizu-provision-2026-09` など、後で消すときに分かるもの）
3. **表示は一度きり**。その場でコピーする

> ⚠ **このトークンはアカウント全体を操作できます。** プロジェクト単位の制限がないため、
> 同じアカウントに他のSupabaseプロジェクトがあれば、それらにも到達できます。
> 構築が終わったら必ず失効させてください。

---

## 2. Vercel トークン

1. https://vercel.com/account/settings/tokens を開く
2. 新しいトークンを作成する。設定項目は3つ:
   - **名前**: `kakeizu-provision-2026-09` など
   - **スコープ**: プロジェクトを作りたいアカウント／チームを選ぶ
     （チームに所属している場合、ここを間違えると個人アカウント側に作られます）
   - **有効期限**: **選べる中で最短にする**（構築時にしか使わないため）
3. **表示は一度きり**。その場でコピーする

---

## 3. Gemini APIキー（★注意が必要）

**ここが一番間違えやすい箇所です。** 無料枠のキーは、入力がサービス品質の改善に
利用され得ます。戸籍を送る以上、**課金が有効なプロジェクトのキー**が必要です。

1. https://aistudio.google.com/app/apikey を開く
2. APIキーを作成する。このとき紐付けるGoogle Cloudプロジェクトを選ぶ（または新規作成）
3. **そのプロジェクトに請求先アカウントを紐付ける**
   - AI Studioのキー一覧に、プロジェクトごとのプラン／ティアが表示されます
   - 無料のままなら、課金設定（Set up billing / プランのアップグレード）へ進みます
   - Google Cloud Console から設定する場合は https://console.cloud.google.com/billing
     でプロジェクトに請求先アカウントをリンクします
4. **キー一覧に戻り、そのプロジェクトが無料枠ではなくなっていることを確認する**

> ⚠ **無料キーと有料キーは文字列を見ても区別できません。**
> 判断材料は「キーの発行元プロジェクトに課金が有効か」だけです。
> ここを確認せずに `AI_NO_TRAINING_CONFIRMED=true` を立てると、
> 確認したという表明だけが立って、実態は無料枠のまま戸籍が流れます。

---

## 4. Anthropic APIキー（推奨）

APIの入出力はモデルの学習に使用されないため、**特別なプラン契約は不要**です。
Geminiのような無料／有料の区別による落とし穴はありません。

1. https://platform.claude.com/ を開く
2. Settings → API Keys から新しいキーを作成する
3. **表示は一度きり**。その場でコピーする
4. 実際に呼び出すには請求設定（クレジットの購入または支払い方法の登録）が必要です

### なぜ2社目を入れるのか

APIキーが2社ぶん設定されると、**2モデル照合が自動的に有効**になります。
別々のモデルで同じ戸籍を解析し、食い違った箇所を「要確認」に一覧表示します。

同じモデルを2回呼んでも同じ誤読を再現するだけなので、**別プロバイダであること**が
条件です。解析は同時に走るため待ち時間は増えません（コストは約2倍）。

月100案件規模でもAPI料金は人手の修正コストより1桁小さいため、
精度を優先して既定で有効にしています（試算は [MODEL_RESEARCH.md](./MODEL_RESEARCH.md)）。

## 5. 設定する場所

取得した値は **Claude Code on the web の環境変数** に設定します。

```
SUPABASE_ACCESS_TOKEN=<手順1の値>
VERCEL_TOKEN=<手順2の値>
GEMINI_API_KEY=<手順3の値>
ANTHROPIC_API_KEY=<手順4の値>
AI_NO_TRAINING_CONFIRMED=true
```

`AI_NO_TRAINING_CONFIRMED` はキーではなく、**手順3・4の要件を満たしたことの表明**です。
本番でこれが `true` でないと、解析は実行されずエラーで停止します。
戸籍を、条件を確認しないまま外部へ送らせないための仕組みです。

> ⚠ **キーをチャットやIssue、コミットに貼らないこと。** 会話ログやGit履歴に残ります。
> 環境変数として設定すれば、値が本文に現れることはありません。

環境変数はコンテナの起動時に読み込まれるため、**設定後は新しいセッションを開いてください。**

---

## 6. 構築が終わったら

- [ ] `SUPABASE_ACCESS_TOKEN` を失効させる（手順1のページから削除）
- [ ] `VERCEL_TOKEN` を失効させる（手順2のページから削除）
- [ ] Vercelの環境変数に `SUPABASE_SERVICE_ROLE_KEY` が入っていることを確認する
      （`pnpm provision` が自動設定。招待メールの送信に必要）
- [ ] `/api/health` で `noTrainingConfirmed` が `true` であることを確認する

上2つを消してもアプリは動きます。消し忘れると、アカウント全体を操作できる
トークンが残り続けます。

---

## キーを入れ替えるとき

- **Geminiのキーをローテーションしたら**、新しいキーの発行元プロジェクトが
  有料ティアかを再確認する（無料枠のキーに戻ってしまう事故が起きやすい箇所）
- **プロバイダを追加したら**、[AI_DATA_POLICY.md](./AI_DATA_POLICY.md) に要件を追記し、
  `lib/analysis/dataPolicy.ts` の `AI_DATA_POLICIES` にも追加する
  （定義漏れは単体テストで検出されます）
