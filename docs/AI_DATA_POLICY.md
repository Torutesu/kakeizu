# AIデータ利用ポリシー（学習に使わせないためのルール）

戸籍は極めて機微な個人情報です。解析のためにAIプロバイダへ送信する以上、
**入力データがモデルの学習に使われない**ことを、運用の心がけではなく
**動く仕掛け**として担保します。

## ルールの全体像

| 層 | 何をするか | 破られた場合 |
|---|---|---|
| 1. コードでの担保 | 設定できるものはコードで固定（OpenAIの応答非保存） | デプロイに含まれるため常に有効 |
| 2. 確認フラグの必須化 | 本番では `AI_NO_TRAINING_CONFIRMED=true` が無いと**解析を実行しない** | 未設定なら機微情報を送る前にエラーで停止 |
| 3. 契約・設定の確認 | 各社ごとの要件（下表）を満たす | 人が確認し、フラグを立てることで表明する |

つまり **「確認していないなら送らない」** が既定動作です。フラグを立てる行為が、
下表を満たしたという表明になります。

## プロバイダ別の要件

### Google Gemini（既定プロバイダ）

- **要件**: 課金が有効な**有料APIキー**を使うこと
- **理由**: 無料枠（AI Studioの無償利用）は、入力がサービス品質の改善に利用され得ます
- **設定**: Google Cloud / AI Studio でプロジェクトに請求先を紐付け、有料ティアのキーを発行して `GEMINI_API_KEY` に設定する
- **注意**: 無料キーと有料キーは見た目で区別できません。**キーの発行元プロジェクトに課金が有効かを必ず確認**してください

### Anthropic Claude

- **要件**: 通常のAPI利用（APIの入出力はモデルの学習に使用されません）
- **設定**: Anthropic Console で発行したキーを `ANTHROPIC_API_KEY` に設定する
- **追加対策**: 保持期間そのものを短くしたい場合は、ゼロデータ保持（ZDR）の適用を申請できます

### OpenAI GPT

- **要件**: API経由の利用（既定で学習に使用されません）＋ 組織設定でデータ共有をオフのままにする
- **設定**: Platform で発行したキーを `OPENAI_API_KEY` に設定する
- **コード側の担保**: リクエストに `store: false` を指定し、**応答がOpenAI側に保存されないように**しています（`lib/analysis/providers/openai.ts`）

## 本番での設定手順

1. 上記のうち、**使うプロバイダの要件をすべて満たす**（有料キーの発行、組織設定の確認）
2. Vercelの環境変数に以下を追加する:

```
AI_NO_TRAINING_CONFIRMED=true
```

3. デプロイ後、`/api/health` の `noTrainingConfirmed` が `true` になっていることを確認する

未設定のまま解析しようとすると、次のエラーで**送信前に停止**します:

> AIプロバイダのデータ利用ポリシーが未確認のため解析を実行できません。

開発環境（ローカル）では警告ログのみで続行します。テストデータでの検証を妨げないためです。

## 定期的な確認

- **キーをローテーションしたとき**: 新しいキーが有料ティアのものかを再確認する
- **プロバイダを追加したとき**: 上表に要件を追記し、`lib/analysis/dataPolicy.ts` の `AI_DATA_POLICIES` にも追加する（テストで定義漏れを検出します）
- **契約や規約が変わったとき**: 各社の最新のデータ利用条件を確認する

## 関連する実装

| ファイル | 役割 |
|---|---|
| `lib/analysis/dataPolicy.ts` | 要件の定義と、本番での確認フラグ必須化 |
| `lib/analysis/index.ts` | 解析実行前のゲート（未確認なら送信しない） |
| `lib/analysis/providers/openai.ts` | `store: false` による応答の非保存 |
| `app/api/health/route.ts` | 確認状態の可視化 |
